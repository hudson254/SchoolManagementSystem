# Report Authentication Architecture

## Overview

The Secure Report Authentication system provides a comprehensive framework for ensuring every report generated by the School Management System is uniquely identifiable, tamper-evident, and verifiable. It implements a multi-layered security approach combining:

- **Unique Report IDs** (e.g., MTS-20260728-8F9D23C7A4)
- **Cryptographic Verification Tokens**
- **SHA-256 Hash Signatures**
- **QR Code Verification**
- **Semi-transparent Watermarks**
- **Authentication Banners**

## Architecture Layers

### 1. Domain Layer (`SMS.Domain`)

**Entities:**
- `ReportVerification` - Core entity with all verification metadata
- `ReportVerificationStatus` - Enum: Valid, Revoked, Expired, Pending

**Interfaces:**
- `IReportVerificationRepository` - Data access contract
- `IReportAuthenticationService` - Core service contract

### 2. Infrastructure Layer (`SMS.Infrastructure`)

**Services:**
- `QrCodeService` - QR code generation using QRCoder
- `WatermarkService` - Semi-transparent watermark image generation
- `ReportTokenService` - Cryptographic token & Report ID generation
- `ReportHashService` - SHA-256 hashing & validation
- `ReportAuthenticationService` - Orchestrator combining all services

**Configuration:**
- `ReportAuthenticationOptions` - Configurable settings from appsettings.json

### 3. Persistence Layer (`SMS.Persistence`)

**Repository:**
- `ReportVerificationRepository` - Full CRUD + search operations

**Database:**
- `ReportVerifications` table with indexes on ReportId, VerificationToken, Status, GeneratedDate, ReportType

### 4. Application Layer (`SMS.Application`)

**CQRS Handlers:**
- `GenerateReportAuthenticationCommand` - Create new verification records
- `VerifyReportByTokenQuery` - Verify via token (from QR code)
- `GetReportStatusQuery` - Check status by Report ID
- `RevokeReportCommand` - Admin revocation
- `RestoreReportCommand` - Admin restore
- `GetVerificationHistoryQuery` - Audit trail
- `SearchReportsQuery` - Admin search/filter

**DTOs:**
- `ReportVerificationResponseDto` - Verification result
- `ReportVerificationListDto` - Search results
- `VerificationHistoryEntryDto` - Audit log entries
- `RevokeReportRequestDto` - Revocation request

### 5. Reporting Layer (`SMS.Reporting`)

**Integration Points:**
- `PdfGeneratorService` - Embeds watermark, QR code, auth banner, Report ID
- `ExcelGeneratorService` - Embeds auth metadata
- `ReportingService` - Automatically invokes authentication for every report

### 6. API Layer (`SMS.API`)

**Controllers:**
- `ReportVerificationController` (Public) - Token verification, status check
- `ReportAdminController` (Protected) - Search, revoke, restore, export

## Verification Flow

```
1. Report Generation
   └─> ReportingService.GenerateReport()
       └─> ReportAuthenticationService.GenerateAuthenticationAsync()
           ├─> Generate unique Report ID (MTS-YYYYMMDD-XXXXXXXX)
           ├─> Generate secure verification token (64 char hex)
           ├─> Compute SHA-256 hash of report content
           ├─> Generate verification URL
           ├─> Generate QR code from URL
           ├─> Persist verification record
           └─> Return auth data (Report ID, QR code, token)

2. QR Code Scan
   └─> User scans QR code
       └─> Opens verification page: https://<server>/verify/report/{token}
           └─> ReportVerificationController.VerifyByToken()
               └─> ReportAuthenticationService.VerifyReportByTokenAsync()
                   ├─> Validate token format
                   ├─> Look up database record
                   ├─> Check revocation status
                   ├─> Check expiration
                   ├─> Validate hash (if content provided)
                   └─> Return verification result

3. Verification Result
   ├─> Valid    - "Authentic system-generated report"
   ├─> Invalid  - "Report not found in system"
   ├─> Revoked  - "Report has been revoked" + reason
   ├─> Expired  - "Report has expired"
   └─> Tampered - "Content has been modified"
```

## Database Schema

```sql
CREATE TABLE ReportVerifications (
    Id UUID PRIMARY KEY,
    TenantId UUID NOT NULL,
    ReportId VARCHAR(50) NOT NULL UNIQUE,
    VerificationToken VARCHAR(128) NOT NULL UNIQUE,
    ReportType VARCHAR(100) NOT NULL,
    ReportName VARCHAR(500) NOT NULL,
    GeneratedByUserId VARCHAR(100) NOT NULL,
    GeneratedByUserName VARCHAR(200),
    GeneratedDate TIMESTAMP NOT NULL,
    SHA256Hash VARCHAR(128) NOT NULL,
    HashAlgorithm VARCHAR(50) NOT NULL,
    Status VARCHAR(50) NOT NULL,
    VerificationCount INT DEFAULT 0,
    LastVerified TIMESTAMP,
    ExpirationDate TIMESTAMP,
    RevokedDate TIMESTAMP,
    RevokedBy VARCHAR(100),
    RevocationReason VARCHAR(500),
    WatermarkEnabled BOOLEAN DEFAULT TRUE,
    WatermarkText VARCHAR(500),
    Version INT DEFAULT 1,
    Remarks TEXT,
    CreatedAt TIMESTAMP NOT NULL,
    UpdatedAt TIMESTAMP NOT NULL,
    IsDeleted BOOLEAN DEFAULT FALSE,
    CreatedBy VARCHAR(100),
    ModifiedBy VARCHAR(100),
    CreatedDate TIMESTAMP,
    ModifiedDate TIMESTAMP,
    DeletedDate TIMESTAMP,
    DeletedBy VARCHAR(100),
    RowVersion BYTEA
);

CREATE INDEX IX_ReportVerifications_ReportType ON ReportVerifications(ReportType);
CREATE INDEX IX_ReportVerifications_GeneratedDate ON ReportVerifications(GeneratedDate);
CREATE INDEX IX_ReportVerifications_Status ON ReportVerifications(Status);
CREATE INDEX IX_ReportVerifications_TenantId ON ReportVerifications(TenantId);
```

## Security Measures

1. **Token Generation**: Uses `System.Security.Cryptography.RandomNumberGenerator` for cryptographically secure random tokens
2. **Hash Algorithm**: SHA-256 for tamper detection
3. **Rate Limiting**: Verification endpoints protected by rate limiting middleware
4. **Authorization**: Admin endpoints protected by RBAC (AdministratorAccess, ModeratorAccess)
5. **Public Endpoints**: Return minimal metadata only
6. **Tenant Isolation**: Global query filters ensure multi-tenant data isolation
7. **Audit Logging**: Every verification attempt logged with IP, user agent, timestamp
8. **Anti-Enumeration**: Tokens are non-sequential, non-predictable

```json
{

    "VerificationEndpoint": "/api/v1/verify/report",
    "DefaultWatermarkText": "Official System Generated Report",
    "WatermarkEnabled": true,
    "QrCodeSize": 150,
    "QrCodePlacement": "Footer",

  }

```

## API Endpoints

### Public (No Auth Required)
- `GET /api/v1/verify/report/{token}` - Verify by QR token
- `POST /api/v1/verify/report/verify` - Verify with optional content hash
- `GET /api/v1/verify/report/status/{reportId}` - Check report status

### Admin (ModeratorAccess Required)
- `GET /api/v1/admin/reports/search` - Search and filter reports
- `GET /api/v1/admin/reports/history` - Get verification history
- `GET /api/v1/admin/reports/statistics` - Verification statistics
- `POST /api/v1/admin/reports/revoke` - Revoke a report
- `POST /api/v1/admin/reports/restore` - Restore a revoked report
- `GET /api/v1/admin/reports/export` - Export verification logs

## Report ID Format

Format: `MTS-YYYYMMDD-XXXXXXXX`

- `MTS` - School prefix (Management Training School)
- `YYYYMMDD` - Generation date
- `XXXXXXXX` - 10-character hex string from secure random

## Verification Token Format

- 64 bytes (128 hex characters) generated via `RandomNumberGenerator`
- Non-sequential, non-predictable
- Unique constraint in database
- Resistant to brute-force attacks

## Audit Logging

Every verification attempt records:
- Timestamp
- Report ID and Token
- Verification result (Valid/Invalid/Revoked/Expired/Tampered/Error)
- Authenticated user (if available)
- Source IP address
- User agent / Device information
